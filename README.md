### Использованные концепции ОС Linux и C++ 
1) Создание демона (двойной форк) и контроль его запуска: 
   - fd: open, close
   - Processes: pid, pgid, sid
   - signals
   - Single Instance Control: flock (lock-file, pid-file)
   - Daemonization: fork, dup2, umask, chdir, stdio>>/dev/null
   - Управление loop: volatile, sig_atomic_t

2) Визуализация в консоли (библиотека ncurses).

3) Добавил взаимодействие демона и клиента через unix-сокет (AF_UNIX).

НЕ РЕАЛИЗОВАНО:  ТЗ.2.4. "Обработка системных сигналов"

НЕ РЕАЛИЗОВАНО: ТЗ 4.1
    **Ресурсоемкость парсера:** Процесс сбора данных демоном при секундном интервале не должен превышать 0.5%
утилизации одного ядра CPU. Не допускается постоянное переоткрытие дескрипторов файлов `/proc`, указатель
текущей позиции должен эффективно сбрасываться в начало через `seekg` / `lseek`.

НЕ РЕАЛИЗОВАНО: ТЗ 4.2
   **Устойчивость IPC-канала:** Приложение демона защищено от падения по сигналу `SIGPIPE`. Если клиент аварийно
   завершает работу посередине трансляции пакета, демон корректно обрабатывает код ошибки системного вызова
   `write` / `send`, закрывает дескриптор этого клиента и продолжает обслуживать цикл сбора.

НЕ РЕАЛИЗОВАНО: ТЗ 4.3
   **Корректность завершения терминала:** Независимо от причин выхода из интерфейса (нажатие `Q`, сигнал
   `SIGINT`, обрыв сокета), клиент обязан гарантированно выполнить деструктор ncurses, исключая порчу
   отображения текущей командной строки пользователя.
